Prove a human wrote it.

Open protocol. Hardware-backed. No trust required.

AI can produce text indistinguishable from human writing. Every detection tool that analyzes the output is losing an arms race it can never win. The next model will always evade the last detector.

Speakwrite takes a different approach: instead of analyzing what was written, it captures how it was written. Keystroke dynamics, commitment chains, and hardware-backed signatures create a portable proof that anyone can verify.

The Problem

The internet has a trust crisis. You can no longer look at a piece of text and know whether a person wrote it. AI detection tools try to solve this by analyzing the output — word choice, perplexity, sentence structure. But these tools are fundamentally fragile: each new model defeats the last detector.

Meanwhile, there is no place to go where everything you see was provably typed by a human. No feed, no platform, no protocol for it.

We think the solution isn’t better output analysis. It’s capturing the process of writing and making it verifiable.

The Approach

Speakwrite doesn’t analyze what you wrote. It records how you wrote it.

As you type, the app captures your keystroke dynamics — timing, rhythm, pauses, corrections — and periodically creates cryptographic commitments chained together with SHA-256 hashes. Each checkpoint is signed by the iPhone’s Secure Enclave. When you publish, the entire proof chain is attached to your post.

The result is a proof bundle: a portable JSON artifact that anyone can independently verify. No server. No API key. No central authority.

How It Works

  1. Sign in Use your AT Protocol handle. OAuth authentication, decentralized identity.
  2. Type Keystroke dynamics — timing, rhythm, pauses, corrections — are captured natively as you write. Nothing leaves your device.
  3. Commit Periodically, behavioral features are extracted and hashed into a cryptographic commitment chain. Each link is signed by the Secure Enclave.
  4. Publish The final content is bound to the chain tip. The proof bundle is published alongside your post on the AT Protocol network.
  5. Verify Anyone can check the proof. Walk the hash chain, verify the signatures, confirm content binding. No trust required.

The Protocol

The proof bundle is the protocol. It’s a JSON object that contains everything needed to verify a post was typed by a human. No proprietary format. No server dependency.

Three layers

Layer 1: Cryptographic commitment chain
SHA-256 hash chain with openable commitments — each link binds the behavioral features and a document snapshot hash. Every commitment can be independently re-derived. You can’t edit the chain or swap the content without breaking it.
Layer 2: Device attestation
The iPhone’s Secure Enclave holds a signing key that never leaves the silicon. Apple’s App Attest certifies the key was generated on a real device running the unmodified app. Every commitment is signed.
Layer 3: Behavioral analysis
Human typing has distinct statistical properties: variable inter-key timing, characteristic digraph patterns, natural pause distributions, error-and-correct sequences. These features are captured and committed.

Verification

Anyone can verify a proof bundle:

  1. Content hash Compute SHA-256 of the post text. Compare to the bundle’s content_hash.
  2. Chain integrity + re-derivation Walk the commitment chain. Re-derive each behavioral commitment from its nonce, features, and document hash. Every link must match.
  3. Content binding The final commitment must bind the content hash to the chain tip. The last behavioral commitment’s document hash must match the published content hash.
  4. Signatures Verify each checkpoint signature and the final binding signature against the device public key (P-256 ECDSA).
  5. Plausibility Check keystroke count vs content length, typing speed bounds, and timestamp monotonicity. Non-fatal warnings flag anomalies.

Why It Matters

For writers

Say “I typed this” and have it mean something cryptographically verifiable. Not a badge from a platform. Not a claim on your honor. A proof anyone can check.

For readers

A feed where everything was typed by a person. Not filtered by an algorithm guessing what’s human. Filtered by cryptographic proof.

For the ecosystem

An open protocol that any app can implement. Verification is pure math — SHA-256 and P-256 ECDSA. No vendor lock-in. No central authority.

For trust

One proof is weak. A corpus of proofs from the same identity, exhibiting consistent behavioral patterns over time, is strong evidence. Trust builds progressively.

Honest Assessment

It proves

A post was composed through physical typing on a genuine Apple device, with keystroke behavior consistent with human motor patterns, signed by hardware that never left the silicon.

It doesn’t prove

That the ideas are original, that no AI was consulted, or that the author didn’t read something from another screen and retype it. It makes deception expensive — not impossible.

This honesty is a design choice, not a limitation. Speakwrite produces forensic evidence, not mathematical certainty.

Properties

Open protocol
The proof bundle is JSON. The verification algorithm is public. Anyone can build a verifier, a compatible client, or an alternative implementation.
Hardware-backed
Secure Enclave + App Attest on every proof. The signing key never leaves the silicon. No web fallback.
On-device
No server sees your keystrokes. Everything runs on your iPhone. Only aggregate statistical features are committed to the proof.
Decentralized
Proofs live in the author’s AT Protocol Personal Data Server. No central server, no trusted authority. Verification is pure cryptography.
AT Protocol native
Full AT Protocol client. Timeline, verified feed, compose, profiles — all in one app. Posts publish to your Personal Data Server. Your data, your server.
Progressive trust
A single proof is weak evidence. A corpus from the same identity with consistent behavioral patterns is strong. Trust compounds over time.

Why a Native App

A web app can’t do this. Hardware attestation requires a native binary — Apple’s App Attest certifies the app hasn’t been tampered with, and the Secure Enclave holds a signing key that never leaves the silicon. No JavaScript bridge. No web wrapper. The entire proof chain happens inside the signed binary.

Why AT Protocol

Speakwrite needs three things from a social protocol: portable identity, user-owned data, and extensibility. AT Protocol provides all three.

Portable identity
Your DID (Decentralized Identifier) is yours. If you move servers, your identity, followers, and proof history move with you. No platform lock-in.
Personal Data Server
Proofs are stored as custom lexicon records (io.speakwrite.proof) on the author’s own PDS. The data lives where the author lives — not on a third-party server Speakwrite controls.
Custom lexicons
AT Protocol lets any app define new record types. Speakwrite publishes proof bundles alongside posts using a custom lexicon. Any AT Protocol client can read and verify them.
Federated verification
Because proofs live on the open network, any verifier can fetch and validate them. No API key. No special access. The data is already public in the author’s repository.
Open ecosystem
AT Protocol is not one app. It’s an open network of interoperable services. Speakwrite is a native client that reads, writes, and extends the protocol — not a walled garden built on top of it.
